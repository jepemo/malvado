## Version and scope audit

The engine, crate workspace and both SDK metadata records identify
`2.0.0-alpha.7`. The C and Rust ABI revision is 2. Installed probes validate the
exact engine release and declared ABI/layout before accepting native calls.
[Alpha.6](2.0.0-alpha.6.md) remains accepted at its recorded candidate and its
scope is unchanged. [Family integration](2.0.0-alpha.7-integration.md),
[CLI acceptance](../development/alpha7-rust-cli.md),
[language support](../api/language-parity.md) and the
[compatibility policy](../api/compatibility.md) define the delivered boundary.

Ordinary Rust structs/futures and checked native handles are the supported safe
API. No macro crate or second scheduler is needed. Cargo owns Rust project
metadata; the installed CLI selects one native `game` target. Static SDK linking
is accepted; dynamic-only SDKs, cross-compilation and crates.io publication are
not delivered. Public dynamic C/Lua/Rust payload conversion is not promised.
Breaking changes within 2.x remain possible until the owner requests a freeze.

Windows/Android validation stays in alpha.8. Physical input devices, audible
output and complete manual author/player flows stay in beta. The full aligned
teaching catalog, minigames and new engine families remain future roadmap work.
Source distribution archives are beta/2.0 release preparation, not alpha.7 work.

Any later source revision selected for a tag or published package must pass its
own complete CI and artifact checks. Tagging and release publication were authorized separately and are recorded
above. Future publications still require their own explicit request.
