# 2.0.0-alpha.1: primer corte del runtime C

Estado: implementación inicial de alpha.1, aún no versión completa. El motor anterior y sus ejemplos LÖVE siguen disponibles. El nuevo ejecutable incorpora Lua 5.4.8 y enlaza raylib 5.5. CMake obtiene Lua y raylib en el directorio de build la primera vez y verifica sus hashes SHA-256; el ejecutable incluye Lua compilado. Las versiones y avisos se conservan en sus fuentes.

## Compilar y ejecutar

Se necesitan CMake 3.20+, compilador C/C++ y conexión para la primera descarga de Lua y raylib. En macOS:

```sh
cmake -S . -B build
cmake --build build
ctest --test-dir build --output-on-failure
./build/malvado-run examples/alpha-hello/main.lua
```

Escape o cerrar la ventana termina el ejemplo. `malvado-run --headless juego.lua` ejecuta sin ventana; los scripts headless deben terminar sus procesos. Para usar fuentes locales, pasar `-DFETCHCONTENT_SOURCE_DIR_RAYLIB=/ruta/a/raylib-5.5` y `-DFETCHCONTENT_SOURCE_DIR_LUA=/ruta/a/lua-5.4.8`; en ese caso el desarrollador debe comprobar su procedencia y versión.

## API de este corte

`require("malvado")`, `process(fn)`, constructor `{...}` que devuelve ID, `frame()`, `start(init, options)`, `clear_screen(r,g,b)`, `key("escape")`, `draw_text(text,x,y,size)`, `font(size,r?,g?,b?,a?)`, `write(font,x,y,text)`, `change_text(id,text)` y `delete_text(id)`. Las fuentes usan la fuente predeterminada de raylib; los textos permanecen visibles hasta borrarlos o cerrar el runtime. `draw_text` es dibujo inmediato por tick: hay que llamarlo antes de cada `frame`. `write` es persistente; alineación y los parámetros opcionales de posición/fuente en `change_text` siguen pendientes. Los procesos creados durante un tick se ejecutan en el siguiente. `frame()` fuera de un proceso falla. Una excepción de proceso imprime traceback y devuelve un estado de salida distinto de cero.

El modo gráfico usa un acumulador de 60 ticks por segundo independiente del render, con un máximo de 5 ticks de recuperación por presentación; el tiempo descartado se cuenta internamente. El reloj C admite deltas inyectados en pruebas; el modo headless avanza un tick por iteración. La API C opaca, el contrato de `self` en userdata, limpieza/semántica completa, fuentes externas, señales y compatibilidad con ejemplos antiguos siguen pendientes. La apertura, dibujo y cierre de una ventana con texto se han probado en macOS; falta aceptación visual interactiva y validación en Linux. Android y Windows se validan en alpha.6. La discrepancia de licencias del código histórico sigue pendiente de resolución antes de publicar.

## Siguientes pasos

Continuar separando scheduler y backend del runner, añadir una API C opaca y completar gestión de recursos; probar ventana y ejemplo real en los sistemas objetivo; continuar el checklist de [alpha.1](README.md). Este corte no declara terminada la versión alpha.1.
