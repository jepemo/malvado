# 2.0.0-alpha.7: multi-language architecture and first-class Rust

Status: started after alpha.6 acceptance. The [initial baseline](2.0.0-alpha.7-baseline.md) records structure decisions, native gaps, and partial implementation. A7.1–A7.5, A7.11 and A7.12 are complete. The unsafe Rust sys SDK and installed external consumer pass on macOS and Linux; the owned async adapter, safe process API and Lua relocation pass their required host checks, including Miri and native sanitizer integration. The native lifecycle and owned async design are verified; the [architecture](../architecture/multi-language.md) still requires the platform and visual parity work in A7.6. Alpha.6 scope and completion status are unchanged. Windows and Android validation follow in [alpha.8](2.0.0-alpha.8.md). Beta owns release-facing documentation and candidate review. Future API expansion, the complete example catalog, minigames and website redesign move to the [unassigned roadmap](../roadmap/README.md).

Owner direction: a C-first engine and one scheduler with first-class C, Lua and Rust; Rust processes should feel like structs with sequential async behavior. The field representation, macros and exact signatures are proposals pending proof. No separate scheduler, new ECS, `position` requirement, full physics, modes 7–9, GUI, Lua replacement, or automatic cross-language interop is included.

Rust will have one supported idiomatic safe API, with explicit ownership and errors. Do not reproduce Lua aliases or parallel process styles. Final async signatures remain subject to the scheduler proof. Keep CMake and the native tree in place, except for the approved Lua binding relocation in A7.11; introduce only Rust crates that contain implemented behavior.

Windows and Android: record unresolved toolchains and defer platform claims to alpha.8; do not claim cross-export. For mixed C/Lua/Rust contexts, attempt a bounded internal coexistence test if the public C API permits it; user-facing dynamic mixing, type conversion and payloads remain later work.

Before A7.2, test SDK discovery and ABI mismatch on a clean prefix. Before A7.7, test packaging and dynamic loader behavior on a clean runner. Redesign if safe ownership requires mutable aliases, if a wake queue independently schedules processes, if native handles cannot survive cleanup correctly, or if supported hosts require undocumented source-tree paths.
