# 2.0.0-alpha.7: multi-language architecture and first-class Rust

Status: started after alpha.6 acceptance. The [initial baseline](2.0.0-alpha.7-baseline.md) records structure decisions, native gaps, and partial implementation. A7.1 remains open; no Rust SDK is available yet. The [architecture](../architecture/multi-language.md) and [scheduler design](../specs/rust-processes.md) still require the stated safety and parity proofs. Alpha.6 scope and completion status are unchanged. remaining API families follow in [alpha.8](2.0.0-alpha.8.md); Windows and Android validation follow in [alpha.9](2.0.0-alpha.9.md), and the complete website and distribution review in [alpha.10](2.0.0-alpha.10.md).

Owner direction: a C-first engine and one scheduler with first-class C, Lua and Rust; Rust processes should feel like structs with sequential async behavior. The field representation, macros and exact signatures are proposals pending proof. No separate scheduler, new ECS, `position` requirement, full physics, modes 7–9, GUI, Lua replacement, or automatic cross-language interop is included.

Rust will have one supported idiomatic safe API, with explicit ownership and errors. Do not reproduce Lua aliases or parallel process styles. Final async signatures remain subject to the scheduler proof. Keep CMake and the native tree in place; introduce only Rust crates that contain implemented behavior.

## Ordered work and acceptance gates

Each item requires its tests, docs and stated contract before it is checked. Relative complexity is S, M or L. Modules are expected locations, not a requirement to move existing files. An item blocks its successors where indicated.

- [ ] **A7.1 Native inventory and architecture (M).** Prerequisite: alpha.6 complete. Inspect `src/include/malvado`, core, binding, CLI, CMake and inventory; map every accepted graphics, input, audio, collision, process and resource operation to C and Lua. Identify missing C hooks, define ownership and error contracts, and baseline native/Lua traces. Deliver mapping and approved boundary decisions; no Lua change without parity tests. Risk: incomplete native API. Gate: reviewer can identify every wrapper and gap; blocks A7.2–A7.6.
- [ ] **A7.2 FFI and installed SDK (M).** Prerequisite A7.1. Add `bindings/rust/` workspace and `malvado-sys` with checked declarations; specify native ABI/version discovery and fail incompatible libraries before calls. C API may need a version query. Test C ABI/layout, invalid SDK, static/dynamic dependencies, external consumer from installed prefix, macOS/Linux debug/release. C-only and Lua-only builds work with Cargo absent. Risk: ABI drift and duplicate libraries. Gate: reproducible installed consumer and error diagnostics; blocks A7.3.
- [ ] **A7.3 Scheduler proof (L).** Prerequisite A7.2. Prototype native callback, pinned future, context lifetimes, supported wake mechanism and `frame().await` without a second scheduler. Add C callback/cleanup hooks only if documented and needed. Test first activation, spawn timing, frame and cadence traces, locals across awaits, Pending/Ready, sleeping, freezing, no busy polling, and C/Lua scheduling parity. Risk: self-reference and reentrancy. Gate: sound ownership and deterministic traces under Miri/sanitizers; failure requires redesign, not unsafe lifetime fabrication. Blocks A7.4 and A7.5.
- [ ] **A7.4 Process ergonomics (L).** Prerequisite A7.3. Implement `malvado` typed state, context-bound native handles, process creation and async run; add `malvado-macros` only where validated. Native properties remain authoritative. Define compile-time diagnostics and document generated behavior. Test alias prevention with compile-fail cases, stale/foreign handles, canonical identity, first activation and state preservation. Lua contract unchanged. Risk: borrow ergonomics. Gate: runnable minimal process with no hidden duplicated state; blocks examples and lifecycle completion.
- [ ] **A7.5 Lifecycle and cleanup (L).** Prerequisites A7.3–A7.4. Implement attached/detached spawn, genealogy, signals, kill, kill-tree, sleep/freeze, cancellation and shutdown through C semantics; add C hooks only where necessary. Test natural return, external/self kill, child ownership, creator versus owner, safe-point deferred destruction, wake-after-drop, panic containment, stale handles, exactly-once Drop, resource release and stress. No unwind across C; document `panic=abort`. Risk: use-after-free or double drop. Gate: sanitizer and parity traces pass; blocks resource and release gates.
- [ ] **A7.6 Graphics, input, collisions and resources (L).** Prerequisites A7.1, A7.2, A7.5. Wrap actual alpha.6 C capabilities: images/atlases/sprites, graphs, shapes, transforms, drawing, fonts, keyboard/mouse, audio, collision queries and world movement. Add missing public C operations with contracts and Lua parity, not Rust algorithms. Test RAII/transfer, invalid context, headless graph/collider override, type/handle queries, world and fast movement, plus graphics smoke and shared C/Lua/Rust fixtures. Risk: native coverage or resource lifetime. Gate: inventory mapping and all delivered alpha.6 behavior tested.
- [ ] **A7.7 CLI and external SDK (L).** Prerequisites A7.2, A7.4–A7.6. In existing client/templates, define project detection, `new --lang rust`, Cargo build/run/check/export, SDK discovery and doctor diagnostics; retain `--c` and existing Lua behavior. Decide manifest metadata without duplicating Cargo.toml. Test missing Cargo/SDK, bad config, paths with spaces, incremental build, and independent project create/build/run/export. Never install a toolchain without consent. Risk: ambiguous detection and packaging. Gate: installed SDK works with no source-tree paths; blocks final packaging.
- [ ] **A7.8 Examples and mini-game (M).** Prerequisites A7.4–A7.7. Add runnable Rust hello, circle/square, parent/attached and detached bullets, sequential boss, and world-movement platform example. Use shared assets and compare collision fixtures with current Lua example. Deliver one compact polished Rust game with controls, asset licenses, readable source and smoke test; identify a suitable Lua counterpart. Test compile, bounded run and cleanup. Risk: examples demand undelivered engine features. Gate: every example runs using only delivered APIs.
- [ ] **A7.9 CI and packages (L).** Prerequisites A7.5–A7.8. Add Rust format, clippy, unit and headless integration jobs, C sanitizers, installed SDK consumer and example smoke tests on available macOS/Linux runners. Verify C-only and Lua-only builds without Rust. Test player artifacts on clean automated runners without Cargo or compilers; include native dependencies and notices. Document architecture/profile and any unavailable runner. Windows and Android support requires alpha.9 evidence, not assumptions. Risk: SDK and linker reproducibility. - [ ] **A7.10 Documentation and closure (M).** Prerequisites A7.1–A7.9. Add Rust getting started, reference, scheduler and cancellation guide, runnable snippets and language parity matrix. Gate: all links and snippets validated; no unchecked required item.

## Validation matrix and decisions

Linux and macOS: C-only without Lua/Rust/raylib, Lua without Rust, Rust workspace and installed consumer, headless parity, sanitizer tests and bounded graphics smoke where available. Windows and Android: record unresolved toolchains and defer platform claims to alpha.9; do not claim cross-export. For mixed C/Lua/Rust contexts, attempt a bounded internal coexistence test if the public C API permits it; user-facing dynamic mixing, type conversion and payloads remain later work.

Before A7.3, test pinned future construction, cancellation during poll, wake after termination, native scheduler ordering and panic boundaries. Before A7.2, test SDK discovery and ABI mismatch on a clean prefix. Before A7.7, test packaging and dynamic loader behavior on a clean runner. Redesign if safe ownership requires mutable aliases, if a wake queue independently schedules processes, if native handles cannot survive cleanup correctly, or if supported hosts require undocumented source-tree paths.

Owner review must resolve the final state/handle ergonomics, frame/waker scope, macro syntax, CLI language selection and metadata, native ABI policy, static versus dynamic distribution, and which mixed-language interactions are exposed. Preferred technical choices and tradeoffs are in the linked proposals.
