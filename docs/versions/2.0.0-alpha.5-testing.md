# Alpha.5 automated verification

These checks ran on macOS arm64 on 2026-11-04. The tested implementation was commit `3896912`. The later verification commit changes this record and the version checklist. These are local results; they do not claim a new Linux or Windows CI run.

The build directories use Debug builds. `build-lua-headless` includes Lua and atlas assets without raylib. `build-c` has Lua, raylib, and assets disabled. `build-visual` includes Lua, assets, raylib, and the visual tests. `build-alpha5-sanitize` adds `-fsanitize=address,undefined -fno-omit-frame-pointer` to a Lua headless build without assets. `build-sanitize-sdk` uses the same sanitizer flags for a C-only build with assets.

```sh
cmake --build build-lua-headless -j4
ctest --test-dir build-lua-headless --output-on-failure
cmake --build build-c -j4
ctest --test-dir build-c --output-on-failure
cmake --build build-visual -j4
ctest --test-dir build-visual --output-on-failure
cmake --build build-alpha5-sanitize -j4
ctest --test-dir build-alpha5-sanitize --output-on-failure
cmake --build build-sanitize-sdk -j4
ctest --test-dir build-sanitize-sdk --output-on-failure
```

The results were 89/89 headless, 16/16 C-only, 117/117 visual, 88/88 sanitized headless, and 17/17 sanitized C-only tests. These runs include C/Lua parity, mixed processes, a 512-level tree, the 5,000-round session, and injected spawn, query, handle, and startup allocation failures.

The graphics build with sanitizers used the existing downloaded dependency sources:

```sh
cmake -S . -B build-alpha5-visual-sanitize -DCMAKE_BUILD_TYPE=Debug \
  -DCMAKE_C_FLAGS='-fsanitize=address,undefined -fno-omit-frame-pointer' \
  -DMALVADO_BUILD_LUA=ON -DMALVADO_BUILD_RAYLIB=ON \
  -DMALVADO_BUILD_ASSETS=ON -DMALVADO_VISUAL_TESTS=ON \
  -DFETCHCONTENT_SOURCE_DIR_LUA="$PWD/build/_deps/lua-src" \
  -DFETCHCONTENT_SOURCE_DIR_RAYLIB="$PWD/build/_deps/raylib-src" \
  -DFETCHCONTENT_SOURCE_DIR_CJSON="$PWD/build/_deps/cjson-src"
cmake --build build-alpha5-visual-sanitize -j4
ctest --test-dir build-alpha5-visual-sanitize \
  -R '^(visual_resource_lifetime|visual_image|visual_font|visual_atlas_animation|lua_spawn_allocation|c_process_handle)$' \
  --output-on-failure
MALVADO_REAL_AUDIO=1 ./build-visual/audio-visual-test tests/audio_resource.lua
MALVADO_REAL_AUDIO=1 ./build-alpha5-visual-sanitize/audio-visual-test tests/audio_resource.lua
```

The six selected sanitized graphics and allocation tests passed. Both audio commands passed with the silent fixtures and the local audio backend. These audio checks do not assess audible output. The Linux `xdotool` title test was not run on this host. Android emulator checks remain in alpha.9. Manual user flows, physical devices, audible audio, and clean-computer checks remain in beta.
