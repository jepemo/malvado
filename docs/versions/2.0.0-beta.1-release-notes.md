# Malvado 2.0.0-beta.1

Malvado runs C, Lua and experimental Rust game processes on one native
scheduler. This beta focuses on verifying the delivered engine and its tools.

## What changed

- Added a reference for the delivered C, Lua and Rust APIs, with ownership,
  error and platform limits.
- Added aligned lessons for starting a game, running processes and drawing a
  shared PNG. Each lesson has C, Lua and Rust versions.
- Added a source archive with an exact commit ID and a SHA-256 checksum.
  The source verifier builds and tests the core and an external SDK consumer
  from the extracted archive.
- Added versioned documentation and notices for the libraries integrated
  into the graphical backend.

## SDKs and targets

| Authoring host | SDK target | Game export |
| --- | --- | --- |
| macOS Apple Silicon | `darwin-arm64` | Native folder, macOS app bundle and Android arm64 |
| Linux x86_64 | `linux-x86_64` | Native folder and Android arm64 |
| Windows x64 MSVC (beta) | `windows-AMD64` | Native x64 folder |

Windows x64 and Android arm64 platform support is beta in 2.0.
All three languages can export Android arm64 debug APKs and release APKs or AABs
from the supported macOS and Linux hosts. Android authors need a matching
target SDK and the pinned Android tools. Windows players require a WGL provider
and the Microsoft release CRT. See the candidate SDK guide for requirements.

## Known limits

- Rust gameplay support is experimental. The SDK requires an exact match with
  the native release and validates the ABI. Replace the prior SDK and update
  the path to the matching Rust crate when upgrading an existing project.
- macOS app exports do not include production signing or notarization.
- Desktop exports target the native authoring host. Android has no authoring
  CLI or Windows cross-export path.
- Author-provided dependency runtimes and game-specific notices remain the
  game author's responsibility.

## Candidate evidence

The accompanying platform report identifies the source revision and exact
CI runs. The source verification report identifies the tested source archive.
Use `SHA256SUMS` to verify candidate files before extraction or installation.
