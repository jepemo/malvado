# Alpha.6: process graphics and collision world

Status: in progress. This is part of [alpha.6](2.0.0-alpha.6.md), not a new release. All unchecked items are required to close the collision item in that version. Existing axis-aligned rectangle functions remain supported. A checked item requires its full contract, implementation, documentation, and automated evidence.

## Outcome and boundaries

A process can display a reusable graphic and query collisions with other processes without calculating intersections in Lua. A separate 2D world owns invisible static obstacles and can move a process without tunneling through supported obstacles. The C core works without Lua or raylib. Rendering, process collision, and static world geometry are separate; immediate drawing does not create colliders and background images do not become obstacles.

Use the existing scheduler and process handles. Keep `x`, `y`, `angle`, and uniform `size` as the 2D transform. `z` remains the visual draw order. Do not add `position` or reinterpret `z`. Degrees rotate clockwise in screen coordinates. No GPU readback is permitted. Define ownership, errors, defaults, edge contact, limits, and cleanup in the public contracts before finalizing each API.

## Implementation order

1. Specify contracts and complete backend-independent shape geometry.
2. Add reusable process graphics and explicit/automatic colliders, then integrate rendering and process queries.
3. Add the static world and its queries, then implement and test continuous movement for every advertised shape combination.
4. Complete both examples, performance evidence, compatibility checks, and documentation. Run the release-relevant automated suites.

The world and process layers share C geometry but do not introduce another scheduler. Resolve implementation choices against the existing process lifecycle and rendering contracts; do not change scheduling order for indexing.

## Deliverables and acceptance checks

### Contracts and geometry

- [ ] Specify the C and Lua shape, transform, pivot, lifetime, and error contracts. Circle graphics default to a centered pivot; rectangles default to centered and support `top-left`. Explicit collider offsets are local to the process origin and rotate and scale with it. `nil` derives from the graphic, `false` disables participation, and an explicit shape overrides the graphic. Document how edge contact relates to `mv_rect_overlaps`, numeric limits, and rounding. Test invalid dimensions, non-finite inputs, overflow, defaults, and edge cases in C and Lua.
- [x] Implement reusable C circle and rectangle shapes and world transforms, including rotated rectangles, with a bounding-box rejection before narrow phase. Cover circle-circle, circle-rectangle, rectangle-rectangle, translation, rotation, scale, offsets, pivots, corner cases, and touching boundaries in C; verify Lua parity once bindings exist. Preserve `mv_rect_overlaps` and `mv_rect_contains` behavior.

The C shape tests are in `tests/collision.c`; `tests/collision.lua` checks the same geometry through reusable Lua descriptors.

### Process graphics and colliders

- [ ] Add reusable `graphics.circle` and `graphics.rect` descriptors with color and pivot options. Permit them in process defaults without breaking the existing defaults-copy contract or sharing mutable per-process state. Automatically render `self.graph` using `x`, `y`, `angle`, `size`, and existing `z` order; do not create a second scheduler. Test descriptor sharing, defaults, transforms, color, pivots, draw order, and resource cleanup with headless and automated graphics tests.
- [ ] Support existing images as process graphs and derive collision rectangles from their dimensions. Integrate atlas sprites where the existing representation supports a complete contract; document any unsupported variant instead of silently drawing or colliding incorrectly. Test image and supported sprite dimensions, pivots, transforms, ownership, cleanup, and existing sprite and legacy behavior.
- [ ] Add automatic graphic-derived colliders using the reusable `collision.circle` and `collision.rect` descriptors. Support `nil`, explicit override, and `false`; a process with neither graph nor collider does not participate. Keep descriptors independent from rendering resources. Test reuse, offset transforms, overrides, disabled colliders, missing graphics, invalid inputs, and lifetime in headless C and Lua tests.
- [ ] Provide C process-collider registration and querying using existing process identities and lifecycle. Geometry reflects current transforms; terminated processes leave no stale entries or dangling references. Test registration, updates, removal, allocation failure, cleanup, and C-only operation without Lua or raylib.
- [ ] Add `process.collision(self, target)` and `process.collisions(self, target)` for a process type or specific handle. Return the first canonical handle or `nil`, and a fresh ordered table respectively. Exclude self and logically dead or terminating processes; include sleeping and frozen processes unless disabled. Test creation order, handle identity, type and handle selection, no result, multiple results, same-tick transforms, lifecycle, and many creations and terminations. The first-result query must avoid an unnecessary Lua result table.
- [ ] Use a deterministic broad phase for process candidates, or document a measured alternative that avoids narrow-phase work for every live process on every query. Test index updates after moves, transforms, disabling, and termination. Benchmark many processes and queries, record workload and results, and confirm scheduling and results do not depend on render frequency.
- [x] Decide whether a DIV-style global collision shorthand is unambiguous and compatible with atomic `import_globals`. The global shorthand is omitted to keep shape tests and future process queries distinct. The decision is documented in [collision](../api/collision.md); the existing global import checks remain in `tests/import_globals.lua`.

### Static world and movement

Progress: the C and Lua world can own rectangles and query a transformed shape
with a sorted bounding-box filter and deterministic insertion-order results. See
`tests/collision.c`, `tests/collision.lua`, and [collision](../api/collision.md).
Lua can query live processes with explicit colliders, and C and Lua can sweep
and move circles and rectangles against static rectangles. Automatic graphic
colliders remain open. Allocation failures and cleanup are
exercised by `tests/collision_allocation.c` and the Lua garbage-collection test.

- [x] Add an owned, renderer-independent C 2D collision world and Lua `world.create()` with static rectangles. Define insertion, resource ownership, cleanup, invalid input, and failure behavior. Use world coordinates and a broad phase suitable for static geometry. Test C-only and headless operation, multiple obstacles, query ordering, invalid input, allocation failures, and cleanup. Keep future geometry providers possible without implementing them or a 3D engine.
- [ ] Implement world queries against a process's effective collider at its current transform and at a supplied replacement position. Return documented hit information or no hit, without mutating the process for a proposed-position query. Test both positions, transforms, disabled and absent colliders, invalid handles, multiple obstacles, and C/Lua parity.
- [x] Implement `world:move(process, dx, dy)` and its C equivalent as continuous kinematic movement against the static shapes advertised by the contract. Apply the full displacement when unobstructed; otherwise stop without penetration and report hit, actual movement, and normal. Define initial overlap, tangency, zero movement, tie order, numerical tolerance, unsupported combinations, and errors; do not silently fall back to endpoint-only checks. Test walls, free and diagonal movement, thin obstacles at high speed, starting contact and overlap, repeated movement, transforms, and C/Lua parity. Automatic sliding is not required. Automatic graph-derived colliders remain a separate open item; explicit colliders are supported. Evidence: `tests/collision.c` and `tests/world_process.lua`.

## Explicit exclusions

No pixel-perfect masks, tilemap collision, hardness-map import, gravity, jumping, forces, impulses, rigid bodies, bounce, character controllers, stairs, slopes, 3D movement, or new physics engine. Mode 7 remains planned for 2.1, Mode 8 for 2.2, and Mode 9 for 2.3; their geometry and `z` semantics are separate future decisions. The geometry interfaces and ownership must not preclude later providers, but this alpha does not implement speculative provider frameworks.
