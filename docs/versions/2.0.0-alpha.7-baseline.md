# Alpha.7 implementation baseline

Status: A7.1 complete. The [native boundary review](2.0.0-alpha.7-native-gaps.md)
records operation-level gaps, contracts, and the verified C/Lua trace baseline. This page records initial work;
it does not certify Rust support or close A7.2.

## Structure and language decisions

Keep the existing native source tree and installed C headers. CMake owns native
builds. Cargo will own `bindings/rust/` when the FFI implementation starts.
Create only crates with working code: `malvado-sys` first, then `malvado` after
the scheduler proof. Add no macro crate until a demonstrated need exists.
External games remain ordinary Cargo projects. Do not add an ECS, executor,
parallel Rust implementation, or a second project manifest.

Rust has one supported safe API style. Use owned values, typed handles,
`Result`, RAII, and sequential async process behavior. The unsafe sys crate is
an implementation boundary, not a second recommended gameplay style. Do not
port Lua globals, namespace aliases, legacy constructors, or several process
forms to Rust. Preserve the current Lua contract. Validate the final Rust
process signature through the scheduler proof before documenting it as public.
Native process properties remain authoritative; Rust state holds game data.

function. The maps below supply the operation-level C/Lua correspondence,
ownership, constants, and existing evidence. They describe delivered behavior,
not every historical API.

A public C symbol does not establish full Lua parity. In particular, do not
wrap C image drawing and claim that automatic process graphics are complete.
Do not expose `Process`, `LuaCamera`, registry references, or Lua descriptors
as Rust FFI types.

## Initial native ABI query

`mv_abi_version()` returns `MV_ABI_VERSION` as a fixed-width integer.
`mv_version_string()` returns immutable library-owned release text. Both can
run before context or platform creation and require no cleanup. The release
identifier stays alpha.6 until the version is deliberately advanced; this is
work toward alpha.7, not a completed alpha.7 release.

Bindings must compare the ABI revision exactly before other native calls.
Increment the revision for incompatible public layouts, signatures, calling
conventions, or ownership contracts. The revision does not validate architecture,
optional build features, dependency provenance, or whether the intended library
was selected. SDK discovery must check those separately. Older libraries without
the query fail to link; they cannot be safely probed through this new symbol.

The native test checks the query before initialization and after context cleanup.
The relocated installed-SDK consumer also checks the exported query. Rust
mismatch handling, ABI layout validation, host-profile coverage and sanitizer
proof remain open in A7.2 and A7.3. No Rust toolchain is installed by this work.

## Local verification

On macOS, the initial change passed `mise run test-c` (47 tests) and
`mise run test-headless` (154 tests). These runs include the native version test,
API map checks, relocated installed-SDK consumers, and existing C/Lua parity
checks. They preserve a regression baseline; the full A7.1 trace review is
still pending. `git diff --check` also passed.

Cargo was not available on PATH. No Rust compilation, Miri, Linux, graphics,
or candidate-commit CI result is claimed for this change.

The A7.1 completion run passed `mise run test-headless` (156 tests), including
the new fixed `alpha7_baseline_parity` trace and the mixed C/Lua regressions.
Rust is now pinned in mise; the earlier missing-toolchain note describes only
the initial ABI change.
