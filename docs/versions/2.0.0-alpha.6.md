# 2.0.0-alpha.6: API inventory and assets

Status: in progress. Depends on [alpha.3](2.0.0-alpha.3.md) and the API contracts.

## Scope and planning gate

This version selects the 2.0 API inventory and delivers scroll, regions, collision, one FPG variant, and one Aseprite subset. It does not deliver every API family; the remaining selected families belong to alpha.8. Graphics modes 7–9 and GUI work remain outside 2.0.

The remaining API names, FPG variant, and Aseprite subset are not decided. The inventory and format decisions below must identify their inputs, exclusions, and acceptance tests. Split each selected capability into bounded implementation items before starting it. The version cannot close on an unbounded promise to support a format.

The [process API baseline](../api/process-inventory.md) lists the contracts delivered in alpha.5. Use it when selecting the complete inventory and when adding new API names.

## Execution plan

1. Establish the API inventory from the alpha.5 baseline and pinned references. Record a decision for every selected family and assign the remaining families to alpha.8.
2. Specify scroll, regions, and collision separately, including coordinates, lifetime, errors, C and Lua parity, and graphics or behavior tests. Implement each only after its contract is recorded.
3. Pin an FPG variant and licensed fixtures, then specify the Aseprite subset and rejection behavior. Implement each importer with fidelity and malformed-input tests.
4. Verify every delivered symbol and run the relevant C, headless, asset, and visual suites before closing the version. Manual device and user-flow checks remain in beta. Modes 7–9 and GUI remain outside 2.0.
