# 2.0.0-alpha.6: simple 2D APIs and assets

Status: in progress. Depends on alpha.5 process and resource contracts.

## Outcome and scope

A Lua game can load an asset, select a graphic, play an animation, move in a
collision world, and control the main camera with short procedural calls.
Methods and namespaces remain available. C remains idiomatic and explicit.
All interfaces use the existing native capabilities and one process scheduler.

This plan incorporates the owner's Lua API redesign criteria. It replaces the
previous three broad gates (complete inventory, reference semantics, and all
symbols) with the finite deliverables below. The [baseline evidence](2.0.0-alpha.6-baseline.md)
preserves earlier completed work and partial audits. Those results are not
reset, but they do not prove the new behavior. The [collision plan](2.0.0-alpha.6-collision.md)
remains evidence for the delivered world and collision implementation.

The new loader, graph selection, automatic animation, contextual world calls,
minimal shape constructors, main camera, following, and transform integration
belong to alpha.6. They must not be moved silently to alpha.8. Rust belongs to
alpha.7. Remaining selected 2.0 families belong to alpha.8 after explicit
selection. Modes 7–9 belong to 2.1–2.3; GUI belongs to 2.4.

## Fixed design rules

- Keep `self.file` as the optional default library and `self.graph` as the visual.
  Use `graph`, not `graphic`. Remove modern reliance on `self.fpg` and `self.fpgIndex`.
- `graph()` selects a static resource. `animation()` selects automatic playback.
  Both produce reusable descriptors for `self.graph`; no `self.animation` is required.
- Resolve implicit resources from the running process. Explicit forms work
  without that context. Never use shared mutable file or world globals.
- Support minimal globals, useful methods, and explicit namespaces with the same
  results, errors, ownership, and behavior. Do not export every advanced operation.
- Keep both `start(fn, options)` and returned `game.init` entry forms. Neither
  a mandatory `start()` nor a new `game.load()` is part of this plan.
- Keep native operations in C; keep Lua aliases and context resolution in the
  binding. C uses `mv_` functions, typed data, explicit handles and ownership.
- Keep process identity, parentage, termination, sleep/freeze, `frame()`, local
  `fps`, resource cleanup, collision ordering, and swept movement contracts.
- Use short positional calls and a final options table for uncommon Lua options.
  Reject unknown options. Do not copy Lua overloads into C.

## Decisions and deferred work

- A6-01 must record a small immediate-drawing proposal before changing existing
  corner coordinates, center pivots, fill defaults, or `set_color` behavior.
  The optional unified `draw(graphic, x, y)` is not an approved requirement.
- Visible static world objects need a separate ownership/rendering/removal/camera
  decision. Record the proposal in alpha.6; implementation is an alpha.8 design
  candidate, subject to selection. Keep invisible colliders and visual-only
  geometry; do not introduce hidden processes or claim static circle support.
- Review `set_color`, `font`, `load_font`, `draw_text`, `write`, `change_text`,
  `delete_text`, `clear_screen`, and `fade_to`. Record ordering/color/options and
  clipping inconsistencies plus a short recommendation. Detailed text/font
  redesign is an alpha.8 design candidate; preserve current capabilities now.
- Complex camera composition, smoothing, and configurable follow offsets are
  alpha.8 design candidates, not alpha.6 implementation gates. Keep explicit
  cameras and the viewport/region intersection required by A6-07/A6-09.
- Native `.aseprite`, extra Aseprite export metadata and runtime ZIP mounting
  remain outside this redesign. Extra Aseprite support remains in 2.5; ZIP
  mounting needs an alpha.8 selection decision. ZIP is a container, not a graph.
- Future modes must not force 3D positions, reinterpret 2D z, or make a 3D scene
  another graph. No speculative 3D abstraction is required for alpha.6.
