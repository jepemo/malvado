# 2.0.0: first stable distribution

Status: planned. Depends on [beta.1](2.0.0-beta.1.md). Scope is the delivered
engine with completed C/Lua/Rust integration, CLI and verified platform paths.
It does not promise every historical API or any future-roadmap capability.

## Checklist

- [ ] Close beta acceptance and resolve release-blocking issues on the selected candidate revision.
- [ ] Accept the documented API and support matrix for C/Lua/Rust and macOS/Linux/Windows/Android authoring or runtime targets, with explicit unavailable capabilities.
- [ ] Verify the minimal teaching examples, installed SDKs and exported packages on claimed platforms.
- [ ] Review licenses, dependency notices, artifacts and reproducibility evidence.
- [ ] Add the source archive verified in [beta.1](2.0.0-beta.1.md) to the release pipeline and publish `malvado-<version>-src.tar.gz` alongside the platform-specific binary SDKs. Generate it once per version from the same revision as the SDKs, with its SHA-256 checksum and documented build/dependency requirements. An optional `.zip` must contain the same source tree. Require the clean-extraction build and external C consumer checks to pass on the exact release revision before publication.
- [ ] Publish documentation and artifacts that identify the same source revision, current compatibility policy and known limitations.
- [ ] Publish the stable distribution through the explicitly authorized release process.

Breaking changes within later 2.x releases remain possible until the owner
explicitly requests a compatibility freeze. Each approved change still requires
clear contracts, tests, migration notes and native SDK/ABI mismatch handling.
Future feature selection happens in the [roadmap](../roadmap/README.md), without
preassigned minor versions.

## Rust support policy

Malvado 2.0 supports C, Lua and experimental Rust. The Rust gameplay SDK is
functional, maintained and tested over the shared C scheduler. Its public API
can change in future 2.x releases, with migration guidance for significant
changes and no long-term stability guarantee. This label does not apply to the
C core. `Game` replaces the public Rust `Engine` name before 2.0; acceptance is
tracked in [beta.1](2.0.0-beta.1.md), without reopening completed alphas.
The current owned async API remains the baseline. [Future Rust ergonomics](../roadmap/rust-ergonomics.md)
are proposals without an assigned version and are not 2.0 requirements.
