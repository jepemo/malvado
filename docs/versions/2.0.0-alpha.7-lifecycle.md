# Alpha.7 Rust lifecycle and cleanup evidence

A7.5 is implemented. Rust delegates lifecycle, genealogy and resource ownership
to the existing C core; no new scheduler or C lifecycle hook was needed.

## Delivered behavior

- Attached/detached spawning, parent/creator snapshots, native type queries,
  direct children and recursive descendants, and retained creation lineage.
  `Relation::Ownership` and `Relation::Creation` are explicit. Creation queries
  and tree signals work after the ancestor ends while live descendants remain.
- Single-target signals and explicit tree signals, native sleep/freeze/wakeup,
  kill, natural return, cancellation and context shutdown. `signal` no longer
  takes the experimental boolean tree flag; use `signal_tree` with a relation.
  There is no compatibility alias for that earlier alpha API.
- `Resource<T>` registers owned Rust data with the native resource manager.
  Context/process ownership is separate from retained references. Shared-only
  access, checked retain, owner transfer and exactly-once final release preserve
  the native contract. A retained value can outlive the process and context;
  this does not extend graphics/audio platform service lifetime.
- Callback/factory/resource destructor panics remain inside Rust boundaries.
  Self-kill defers future destruction to the native safe point. A detached spawn
  from a process destructor retains its historical creator through the native
  cleanup rule. Shutdown closes tokens before destructors can spawn again.

No suspended Rust state is exposed through handles. Resource values are owned
and `'static`; compile-fail tests reject borrowed data, mutable shared access,
and cross-thread resource release. Dropping a Rust wrapper releases one native
reference, not the owner's reference. Failed native creation drops the value in
Rust. Failed transfers preserve the previous owner. After context shutdown,
retained reads/clones are valid but transfers fail with `Error::Closed`.

## Verification

The new lifecycle trace is shared by C, Lua and Rust. It checks distinct owner
and creator children, ownership freeze/wakeup, natural return, attached child
cancellation, dead-creator queries and creation-tree freeze/kill. The C/Lua trace
comparison is `alpha7_lifecycle_parity`; Rust reads the same golden fixture.

Thirteen lifecycle tests add nested tree boundaries, type filtering, lineage
pruning, resource promotion/rescue/transfer, foreign/dead/closed owners,
self-cancellation, return error, factory/poll/resource destructor panic, and
2,560 repeated spawns with exactly-once state and native resource release.
Existing A7.3 tests cover frame cadence, late/cross-thread wakes, suspension,
external cancellation and shutdown. Query buffer capacity changes are also
checked with a pure Rust/Miri test; no uninitialized output is exposed.

Local checks pass: the Rust workspace has 35 tests and eight doctests per
profile, with Clippy/format, example smoke, SDK rejection and installed-consumer
checks. Native ASan/UBSan passes all 35 tests. Miri passes seven pure ownership,
wake and query-buffer tests; it does not execute C. C-only tests and the full
Lua headless suite include the new native/language parity checks. The native
host CI jobs run the same Rust checks on Linux and macOS.

`panic=abort`, aborting panic hooks and Rust double-panic aborts cannot be
recovered. The exceptional secondary panic payload retention rule from the
[scheduler proof](2.0.0-alpha.7-scheduler.md) still applies. These limits do not
change the native end reason or permit unwinding across C.

A7.6 remains open for platform resource families, graphics, input, audio, assets,
world/process visual integration and their full C/Lua/Rust parity matrix.
