# Alpha.7 Rust scheduler proof

A7.3 is implemented and locally verified. `malvado` registers native callbacks;
it does not own a second scheduler. The C core and Lua behavior are unchanged.

## Ownership and wake decision

An Engine uniquely owns native context destruction and tick access. It and
its process tokens use owner-thread `Rc` state and are not Send or Sync. A
process receives an owned token, owns its game state, and returns an owned
`Future<Output = Result<(), Error>>`. The future is boxed and pinned. It never
borrows a sibling field through a fabricated lifetime. Game structs can use
`async fn run(self, process: ProcessContext)` and keep mutable locals across
frame waits. Handles expose native snapshots, not suspended Rust state.

A stable native user-data allocation holds the future adapter. Spawn does not
poll it; the factory runs at first native activation, inside panic containment.
A failed native spawn returns responsibility for user data to Rust. Later setup
failure marks the native process for deferred cleanup before returning an error.
The native callback and destructor contracts need no new C hook.

`process.frame().await` requests the next eligible native activation. The
adapter uses native cadence, including first activation and rates 0–60. Sleep,
freeze, wake, ownership cascades, creation order, and priority snapshots stay
native behavior. The frame primitive is a future, not another timing loop.

The waker contains only an `Arc` with atomic readiness and liveness flags. A
wake records readiness; it cannot call C, poll recursively, or choose process
order. Duplicate wakes coalesce. Wake during poll is kept for a later eligible
activation. A future that returns Pending without waking is not polled again
until a wake. Cloned wakers may cross threads; game state and engine operations
may not. This does not supply an asynchronous I/O runtime or permit blocking
callbacks. Native callback visits still occur each eligible tick; only ready
Rust futures are polled.

Natural completion and native cancellation retire the process before dropping
its future at the C safe point. Self-kill does not drop an actively polled future.
Shutdown invalidates tokens before running destructors. Owned handles preserve
their native identity and end reason after shutdown. A late waker retains no
engine pointer and cannot revive a canceled process.

All Rust callbacks entering through C contain unwinding panics. A poll panic
or returned async error becomes a native process error. A destructor panic is
contained; the existing native termination reason is preserved because the
native destructor has no error return. Normal panic payloads are released. If
a panic payload's destructor itself panics, its secondary payload is retained
to prevent another unwind across C. Rust double-panic aborts, aborting panic
hooks, and `panic=abort` cannot be recovered. These limits apply to arbitrary
user destructors; the adapter does not claim to recover from process abort.

## Automated evidence

The Rust golden trace uses the same fixture as the C/Lua parity test, now stored
in `bindings/rust/malvado/tests/fixtures/alpha7_baseline.txt` so installed crate
tests retain it. It checks tick-1 activation, tick-2 detached child activation,
locals across waits, 15 FPS cadence, return, and exactly-once cleanup. All 61
native rates are also compared with the accepted Lua cadence baseline.

Native integration tests cover sleep/freeze/wake, no busy polling, self and
external cancellation, attached/detached creator and owner identities, panic
and error return, destructor panic, shutdown, closed tokens, and wake after
shutdown. Safe handle/property checks are tracked with A7.4.

`mise run test-rust` verifies Debug/Release builds, clippy, formatting, installed
SDK discovery and rejection cases, and the offline external consumer.
`mise run test-rust-miri` passes six pure adapter tests: pinned self-borrowing
locals, cancellation before/after activation, frame waits, wake coalescing,
wake during poll, cross-thread and late wake, and panic/drop containment.
Miri does not execute native C. Its optional dated nightly toolchain is isolated
in `tools/miri/mise.toml`; normal builds keep the stable root toolchain.

`mise run test-rust-sanitize` links the real C scheduler with ASan/UBSan and
executes Rust integration tests. This instruments C accesses; it is not a claim
of sanitizer instrumentation for Rust code. Miri supplies the complementary
Rust future/waker ownership check. Local Miri and sanitizer checks passed on
macOS; both checks are also configured in the macOS/Linux Rust CI jobs.

The complete lifecycle/resource stress matrix remains A7.5. Graphics, window
loops, contextual movement and native visual properties remain A7.6. A7.3
does not complete those gates or authorize a release.
