# Alpha.6 API redesign: initial audit and mapping

Status: planning input for A6-01, not an implemented API reference. The owner
selected the direction below. Exact signatures and unresolved semantics still
need the decision record required by the [alpha.6 checklist](2.0.0-alpha.6.md).

## Current-to-proposed map

Current evidence comes from `src/binding/runtime.c`, `src/binding/globals.c`,
public headers, the drawing/image guides, and the nine example entry files.
This initial inspection does not close the full A6-01 audit.

| Existing API | Minimal Lua target | Explicit Lua / method target | Native C responsibility |
| --- | --- | --- | --- |
| `load_image`, `load_atlas(image, json)`, `load_aseprite(image, json)`, `mv.fpg.parse`, `mv.fpg.parse_manifest` | `load_asset(path, options?)` | Explicit loader in the existing module; useful asset methods | Reuse image/atlas/FPG parsing and metadata ownership. File/schema routing can stay in the binding; new shared capabilities belong in native code. No C aliases for each Lua style. |
| Images and atlas sprites assigned to `self.graph` | `graph(id)`, `graph(asset, id)` with optional `self.file` | `asset:graph(id)`; exact namespace selected in A6-01 | Existing image/atlas identity, retention, pivot/trim and drawing. Add native descriptor operations only where a shared capability is missing. |
| `animation_frame(atlas, name, elapsed, loop)` and manual sprite drawing | `animation(name)`, `animation(asset, name)`, ID-list forms | `asset:animation(name)`; retain advanced sampling | Sequence metadata exists; automatic process-local playback and stable geometry policy need shared native behavior and simulation timing. |
| `mv.graphics.rect`, `mv.graphics.circle` | `rect(w,h,options?)`, `circle(r,options?)` | Keep `mv.graphics` | Alias existing immutable descriptors and native transformed shape drawing; no new geometry engine. |
| `mv.process.collision(self, Enemy)` / imported `process.collision` | `collision(Enemy)` | Keep explicit process query and geometric `mv.collision` | Reuse process/world collision engine and result ordering. Current-process lookup is Lua binding work. |
| `mv.world.create()`, `world:move(self,dx,dy)` | `world_create()`, contextual and explicit `world_move` | Keep world methods and namespace access | Existing sweep, hit data and static rectangles; Lua process association/context must not change movement semantics. |
| `mv.graphics.region` | `region(x,y,w,h)` | Keep `mv.graphics.region` | Existing screen clipping; add camera viewport intersection without changing physics. |
| `mv.graphics.scroll` | `scroll(x,y)` | Keep `mv.graphics.scroll` | Existing process-local translation; integrate one camera projection without applying translation twice. |
| No camera in the inspected modern exports | `camera_set`, `camera_move`, `camera_follow`, `camera_create` | Useful camera methods and explicit namespace selected in A6-01 | Main camera state, projection, lifetime and deterministic following in existing engine flow. Keep native interfaces independent of Lua. |
| `draw_box` / `draw_rect` use corners; filled and outline circle functions are separate | Proposed `draw_rect(x,y,w,h,options?)`, `draw_circle(x,y,r,options?)` | Preserve access to existing capabilities | Existing C primitives already accept dimensions/fill/color. Lua coordinate/fill/color changes need an explicit migration decision first. |
| Both `start` and returned `game.init` | Keep both | All three Lua styles work with both | Preserve startup and shared scheduler, including existing parity tests. |
| Immediate text, persistent text and font functions | Preserve current functions | Record a later focused proposal | Preserve text lifetime, clipping, color and fade behavior; no broad text redesign here. |

## Observed gaps and risks

- Collision/world examples use explicit namespaces and methods. The earlier
  collision plan intentionally omitted a global shorthand. The new owner
  direction supersedes that omission; A6-05/A6-06 must test global import conflicts.
- Region/scroll examples use `mv.graphics` even after `import_globals()`.
  Adding aliases is small; camera integration is a separate behavior change.
- Aseprite and sprites examples advance frames manually. A sampler is not
  automatic playback. A6-04 must establish independent playback and stable
  repeated named lookup before examples use `animation()` in each tick.
- FPG and converted-FPG examples read files and metadata explicitly and load
  images separately. Unification must preserve IDs, pivots and transparency,
  rather than treating a folder or ZIP as a graphics format.
- Current shape descriptors default to center pivots; current immediate
  rectangles take two corners. Do not silently make these equivalent APIs.
- Current graphics documentation distinguishes process graphs, queued immediate
  commands, persistent text and final fades. Main-camera and HUD integration
  needs rendered ordering/clipping evidence, including unchanged physics.
- `import_globals` checks conflicts before installing names and rolls back on
  errors. New aliases must preserve atomicity and standard Lua `load`.

## Required audit completion

Before closing A6-01, inspect and link relevant tests, native implementations,
headers and compatibility code for every changed row. Review `docs/api/drawing.md`,
`images.md`, `collision.md`, `lua-globals.md`, `lua-processes.md`, `lua-contract.md`,
`docs/specs/assets.md`, `graphics-modes.md`, and `docs/architecture/runtime.md`.
Record documentation/source disagreements explicitly. Keep both the native
capability changes and binding-only wrappers visible in the final map.

The example audit covers `collision`, `world-collision`, `scroll`, `regions`,
`fpg`, `fpg_converted`, `aseprite`, `sprites`, and `demo`. Review their assets,
README files and automated example checks as part of the complete audit;
reading entry files alone does not establish rendering or lifetime conformance.
