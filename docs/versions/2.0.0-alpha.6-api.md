# Alpha.6 API audit and decisions

Status: A6-01 complete for the delivered redesign. This records the selected
alpha.6 contracts, source review, differences and bounded deferred proposals.
It is not the complete 2.0 family selection (A6-11), beta API freeze, or final
candidate verification (A6-12). See the [migration guide](../development/alpha6-api-migration.md)
for runnable usage and the [version checklist](2.0.0-alpha.6.md) for closure.

## Current-to-delivered API map

The first column is the implementation before the redesign. Flat module fields
mirror minimal globals where available. Not every operation needs three names.
Errors, ownership and important defaults are recorded here; linked guides give
full numeric limits and failure behavior. All new Lua options reject unknown keys.

## Audit inputs and evidence

Reviewed implementation: public `malvado.h`, `platform.h`, `collision.h`, `atlas.h`,
`fpg.h`, `camera.h` and `animation.h`; core scheduler/process/resource/clock and
new camera/animation implementations; platform image/drawing adapters; asset
parsers; and `src/binding/runtime.c` / `globals.c`, including legacy-only paths.
The core and public headers remain independent of Lua/raylib. C owns explicit
values/handles; Lua wrappers perform context resolution and managed retention.

The nine example sources, README files, included asset metadata and tests were
reviewed in [the migration matrix](../development/alpha6-api-migration.md#reviewed-runnable-examples-and-evidence).
Collision/world, region/scroll, original/converted FPG, Aseprite, sprites and demo
keep their capabilities. Namespace/method, C-only, SDK, lifetime, invalid-input
and pixel checks are linked from the relevant guides and evidence notes.

These records close the alpha.6 review requirement; they do not approve new APIs.

| Question | Small proposal and trade-off | Alpha.6 disposition / destination |
| --- | --- | --- |
| Immediate shape signatures, pivots, fill and color | A future dimensions-based draw call with a final fill/color table would align with constructors. It changes corner-based outlined calls and shared set_color use. Keep center pivots for reusable shapes; make any future immediate origin explicit. | Preserve all existing calls/defaults now. Breaking modernization is an alpha.8 selection/design candidate, requiring a concrete migration decision and pixel tests before implementation. |
| Visible static world geometry | An explicit object could reference physical and visual geometry at one position, with separate enable flags and camera association. ## Contextual wrapper decision (A6-05)

These wrappers closed independently of the broader audit. They require no
native contract changes; the final review is recorded above.

- `world_create()` aliases `mv.world.create()`.
- `world_move(dx, dy)` uses only the scheduled Lua coroutine and its live
  process's `world` field. `world_move(world, process, dx, dy)` and
  `mv.world.move(world, process, dx, dy)` use the supplied objects. The existing
  method stays unchanged. Return tables, validation and sweep behavior are
  delegated to that method's implementation.
- `collision(target)` uses the running process and delegates to the existing
  first-hit process query. Explicit queries remain in `mv.process`.
- The existing `mv.collision` table is callable, like `mv.process`. The imported
  `collision` value is that same table. This preserves the existing global import
  identity/conflict rules and geometric namespace without adding a second
  namespace. Calling it queries processes; named fields construct/test shapes.
- `self.world` is an ordinary retained field. Its type is checked when implicit
  movement uses it. An invalid or absent field raises an error without movement.
  Explicit forms ignore it. Nested user coroutines have no implicit context.
- Existing C ownership, colliders, lifecycle and scheduler remain unchanged.

The old collision-plan omission of a global query is superseded. Existing
modern scripts gain names only through explicit `import_globals()`; an occupied
name causes the existing atomic import error rather than being overwritten.


## Minimal geometry decision (A6-06)

The flat module functions and imported globals `rect`, `circle`, `region`, and
`scroll` are aliases of the existing `mv.graphics` constructor closures. They
keep dimensions, defaults, immutable values, errors and lifetime unchanged.
This is binding-only work; the final asset/camera audit is recorded above.
The namespace remains available and `load` remains the standard Lua function.

Immediate-drawing proposal: use dimensions and explicit fill/color options in a
future focused revision, with examples that compare old corner coordinates to
new dimensions. Disposition for this increment: preserve all existing immediate
functions and `set_color` behavior. No breaking coordinate or fill change is
approved or implemented here. Descriptor pivots remain center by default.


Migration for the completed increments: after `import_globals()`, replace
`mv.graphics.rect/circle/region/scroll` calls with their flat names when useful.
Use `collision(Enemy)` inside a process in place of
`mv.process.collision(self, Enemy)`. Set `self.world` before replacing
`world:move(self, dx, dy)` with `world_move(dx, dy)`. Explicit forms remain
available. New names can conflict with application globals; import fails
atomically rather than overwriting those values. No Malvado 1 compatibility
shim is added.


## Loader and static selection decisions (A6-02/A6-03)

The loader is `load_asset(path, options?)` / `mv.load_asset(path, options?)`.
It reuses existing managed images and native library userdata. No new asset
namespace or duplicate C importer is needed. The documented format option
selects an existing parser; automatic JSON routing checks structure before
native validation. With no window, libraries expose metadata only; a visual
load in initialization also loads images and validates texture bounds.

Static selection uses `graph(id)` with the actual process's `self.file`,
`graph(library, id)`, `library:graph(id)`, and `mv.graphics.graph(library, id)`.
IDs are positive integers. Supported libraries are native/Aseprite atlases,
FPGs and converted-FPG manifests. Descriptors retain the original library and
image; changing `self.file` cannot reinterpret them. Atlas pivot/crop rules
remain unchanged. FPGs use defined control point 0, or a top-left pivot if it
is absent/undefined. Their transparency is selected at loading (true by default).
Converted files use the manifest's points and the PNG's encoded transparency.
Images remain directly assignable to `self.graph`, without `self.file`.

Missing IDs, invalid libraries, absent process/file context and missing visual
images raise errors. Graph descriptors are immutable and reusable. Headless
metadata graphs can provide geometry without textures; using a metadata-only
graph with a later window does not load images implicitly. This extends the
existing native shape/image drawing and collision operations through Lua
wrappers only. The legacy `self.fpg`/`self.fpgIndex` interpretation stays confined
to the explicit legacy profile; modern selection does not use those fields.


The completed selection implementation also shares library userdata in process
`defaults`, like image/graphic descriptors. The same applies to collision worlds,
matching the documented world-context contract: each process retains the supplied
world reference. Ordinary Lua tables still receive independent deep copies.
The previous defaults implementation rejected these native resource references;
`lua_graph_selection` now covers shared `file`/`world` defaults explicitly.


## Camera decisions (A6-07–09)

The native camera is a caller-owned value (`MvCamera`) with an optional viewport,
like the existing value-based shape and fade APIs. It allocates no resource and
needs no Lua/runtime/backend. Lua wraps that value and process association in a
managed camera object; explicit destruction invalidates that shared object.
The main camera is engine-owned, starts at zero and is not destroyable from Lua.

`camera_create(x, y, {viewport = region(...)})`, `camera_set(x, y)` and
`camera_move(dx, dy)` are the minimal API. Set/move also accept an explicit
camera first and have corresponding methods and existing-module namespace
aliases. Position inspection is advanced (`mv.camera.position(camera?)`).
A process camera is nil for main, false for screen space, or a live object.
Closed associations suppress graph/immediate drawing until changed; they do
not change scheduling, physics or persistent text. New invalid associations fail.

Projection is `world - camera - local_scroll + viewport_origin`. Apply it once
through the existing native translation primitive after intersecting viewport,
process region and window clips in screen space. Keep z/creation ordering,
graph-before-immediate, persistent text after processes and fades last. Screen
space alone does not change z. This preserves existing composition, without
introducing a separate HUD layer or advanced split-screen behavior.

Following resolves the target at the end of each existing simulation tick,
after process updates/removals and before drawing. It centers the target's
x/y origin within its viewport (full logical game dimensions by default).
Manual set/move cancels following on success; a new target replaces the old one.
Requests take effect in scheduler call order, with the last successful request
winning. Target termination stops following and retains the last position.
Sleep/freeze preserve the target's current position; invalid positions retain
the last valid camera position. Explicit destruction clears follow references.
The native centering calculation is reusable by C game update code; Lua
process-handle association belongs to the binding, since native game positions
remain caller-owned. Smoothing and offsets remain deferred.


A6-09 uses native `mv_camera_clip` for the viewport/region/window intersection,
with the existing renderer's clip/translation scopes. The combined graphics
regression confirms those scopes restore state between independent cameras,
world processes and screen-space content. Native SDK checks cover extreme
rectangle edges and invalid inputs; no backend is needed for this geometry.


## Animation contract decision (A6-04)

`animation(sequence, options?)` resolves the running process's file; the explicit
form is `animation(library, sequence, options?)`, also available as library methods
and `mv.graphics.animation`. Named native/Aseprite sequences preserve duration
and expanded tag direction, accept only a loop option, and cache identity while
in use. Custom dense ID lists accept fps (default 8) and loop (default true),
including repeated/nonconsecutive IDs. Native playback definitions copy IDs and
microsecond durations; process state advances on the existing 60 Hz simulation
clock independently of local behavior fps. Sleep and freeze pause playback.

Graph replacement resets playback; same-descriptor assignment does not. The first
frame is shown in the selection tick. Non-looping sequences hold the last frame.
The fixed automatic collider is the union of all frame rectangles in local space,
including trim/pivot offsets; explicit collider and false overrides remain.
This policy avoids frame-dependent geometry without imposing a new animation
property. Native C callers keep update/draw/collider control explicit and use the
same immutable sequence/player math. Advanced static sampling and elapsed-time
inspection stay outside the minimal globals.


## Process-based Asteroids acceptance gap

The owner-requested Asteroids rewrite identified a concrete loader/renderer gap:
repeated PNG loads must share native textures, and automatic image drawing needs
an explicit centered pivot. The native PNG cache now uses weak normalized-path
indexing and reference-counted returns, shared by C and Lua. Lua `load_asset`
adds PNG-only `pivot = "center"` / `"top-left"`; its default remains top-left.
This changes no explicit draw_image coordinates and does not reinterpret atlas
pivots. The renderer and automatic collider use the same per-reference pivot.

Image transparency does not select gameplay collision geometry. Asteroids uses
source-space circle approximations with process scale applied once; no polygon
or pixel-mask subsystem was introduced. The example also detects Space presses
with existing key() state and explicitly cleans up independent fragments.
This is a specific alpha.6 acceptance gap, not an expansion to input or mask APIs.
