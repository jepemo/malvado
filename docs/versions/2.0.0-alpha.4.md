# 2.0.0-alpha.4: CLI and desktop SDK

Status: in progress. Builds on the tagged [alpha.3 preview](2.0.0-alpha.3.md); its unchecked verification items remain open.

## Checklist

- [ ] Decide the single user-facing `malvado` command and its `run`, `new`, and optional GUI entry points. See the [CLI proposal](../specs/cli.md#command-name-under-review).
  - [x] Add an initial `malvado new PATH` and `malvado run [FILE]` executable. `run --headless` supports automated checks. Project metadata and GUI commands remain pending.
  - [x] Install `malvado` with CMake and test the installed executable after moving the SDK. Include the Lua, raylib, and cJSON license notices when their components are built.
  - [x] Check project creation, paths with spaces, refusal to overwrite, and headless execution with CTest.
  - [x] Run or check a project directory from another location, including Lua modules and relative assets.
  - [x] Open the generated Lua game in graphics tests on macOS and [Linux CI](https://github.com/jepemo/malvado/actions/runs/41412314091).
  - [x] Add `malvado check [FILE]` to check Lua source syntax without executing it. With no file, it checks the current project directory recursively. Full project, dependency, and asset validation remains pending.
  - [x] Install the C core and optional atlas parser as `Malvado::core` and `Malvado::assets`. Test independent consumers without Lua or raylib. Full SDK packaging remains pending.
  - [x] Add an initial `Malvado::graphics` SDK component and open a window from an independently built C program on macOS and in [Linux CI](https://github.com/jepemo/malvado/actions/runs/41412314091). Desktop package validation remains pending.
  - [x] Add a local SDK archive and SHA-256 checksum task. Extract and test the client and C SDK on macOS and in [Linux CI](https://github.com/jepemo/malvado/actions/runs/41412998629). Clean-machine validation remains pending.
  - [x] Add an initial game launcher that loads `main.lua` and assets relative to its own folder. Test it from another working directory. Release packages remain pending.
  - [x] Add an initial `malvado export PATH` for installed graphical macOS/Linux SDKs. Test an exported Lua game with a module and asset on macOS and in [Linux CI](https://github.com/jepemo/malvado/actions/runs/41416158023). Cross-platform targets and clean-machine packages remain pending.
  - [x] Check the syntax of all included Lua files before export, without executing them. Skip the same build and hidden entries as the exporter. Verified locally and in [CI](https://github.com/jepemo/malvado/actions/runs/41416920814).
  - [x] Allow `malvado export` with no arguments to create `dist/game` without overwriting an existing export.
  - [x] Add an initial `malvado doctor` report for Lua, graphics build, and local export files. Target toolchain and graphics driver checks remain pending.
- [ ] Provide the C SDK, Lua runner, templates, and desktop packages for macOS/Linux.
- [ ] Implement `malvado-cli` project creation, run, check, doctor, and desktop export.
- [ ] Create, run, export, and execute one C game and one Lua game on clean macOS/Linux hosts.
- [ ] Verify package contents, dependencies, notices, and checksums.
- [ ] Document SDK installation, CLI commands, and export workflows.
- [ ] Prepare a release candidate and draft release after package tests pass.
- [ ] Keep project and export services usable by a future GUI. GUI implementation belongs to 2.4.

Windows validation and Android export are in [alpha.6](2.0.0-alpha.6.md). See [CLI](../specs/cli.md), [GUI](../specs/gui.md), and [distribution](../development/distribution.md).

The optional [graphics modes proposal](../specs/graphics-modes.md) can inform future SDK interfaces. Its modes are planned for 2.1 through 2.3 and is not an alpha.4 release gate.
