# 2.0.0-alpha.5: Process model and game entry

Status: in progress. This version finishes the process model and the two Lua game entry forms on the current desktop and headless runtimes. Complete the open alpha.3 and alpha.4 gates in parallel. The detailed design, previous checks, and test evidence are in the [design and evidence archive](2.0.0-alpha.5-notes.md).

Each unchecked item below is a deliverable. Its tests are part of the item. Do not close an item for a partial implementation, a design decision alone, or a test that does not cover the stated behavior. Add a new item only for a specific gap; keep its release gate in this version unless the plan explicitly assigns it elsewhere.

## Scope

Include process identity, lifetime, creation and ownership, Lua handles, process-owned resources, queries, signals, the C/Lua process API, and declarative and explicit game startup. Keep existing C-only use. Keep the current API experimental until beta. Do not add attach/detach, lifecycle hooks, scenes, or general query callbacks.

The complete future namespace inventory belongs to alpha.6. Check the names that exist in alpha.5 here; do not block this version on APIs that do not yet exist. Windows and Android tests belong to alpha.7. Manual user flows and physical devices belong to beta. Automated graphics and failure tests for the current desktop runtimes stay in alpha.5.

## 1. Startup

- [x] Use one scheduler path for `mv.start()` and a returned game table. Check both launchers and ordinary `require` behavior.
- [x] Validate the entry table and window options before opening the window. Call `init` once before the first tick. Check defaults, invalid values, an absent initializer, and an empty game.
- [x] Update the Lua guide, example, project template, and export guide for both entry forms. Record later API inventory and emulator work in alpha.6 and alpha.7.
- [ ] Specify and implement startup failure status and cleanup for context allocation, Lua state allocation, window creation, script load, invalid options, initializer failure, process failure, and shutdown. Report errors without assuming a string. Keep C runner signatures and apply the same policy in headless and windowed runs.
- [x] Add automated failure injection for context, Lua state, and window creation. `lua_start_injection` checks the exit status, acquired context and Lua state cleanup, and a later run in the same host. It runs with headless and graphics builds. `lua_start_failure_cleanup`, `lua_start_cleanup`, and `lua_start_parity` cover other failure paths.
- [x] Verify the declared initial window title with an automated desktop window test. `visual_declarative_start` reads the macOS window title and checks dimensions and rendered pixels; `visual_declarative_title` checks the Linux window title when `xdotool` is available. Keep the packaged launcher and export tests. Test Android exports in alpha.7.

## 2. Process identity and spawn

- [ ] Finish the public C process reference contract and API: context identity, stale references, status, reason, type, creator, owner, and invalid arguments. Specify context lifetime and thread rules. Test foreign and stale references and C-only use.
- [ ] Make Lua spawn transactional after native process creation. Inject Lua allocation failures at each later allocation; verify no live process, scheduler entry, resource, or registry reference remains and input values are unchanged.
- [ ] Finish canonical Lua handle lifetime for native and Lua processes. Test handles retained across return, kill, owner cascade, scheduler cleanup, context shutdown, and a later context. Dead handles retain only identity, status, and reason.

## 3. Termination and ownership

- [x] Specify cleanup order and reentrancy for parent and child snapshots in the [cleanup contract](../api/process-cleanup.md). `lua_cleanup_order` checks dead-handle visibility and parent-before-child cleanup. The implementation and remaining cases stay open below.
- [ ] Finish Lua self-kill and coroutine close behavior. Test direct and tree self-kill in yieldable and non-yieldable contexts, including `pcall`, `__close` errors, and continuation of other cleanup. A killed coroutine must not resume game code.
- [ ] Finish ownership cascades for C and Lua processes. Test different creator and owner trees, external kill, natural return, self-kill, cleanup reentrancy, and exactly-once destruction. Document that a C callback must return after self-kill.

## 4. Resources

- [ ] Document acquisition, ownership, assignment, transfer, explicit release, and thread rules for each current family: images, atlases, fonts, text, sounds, and music. Define shutdown order and C platform resource behavior.
- [ ] Implement and test the documented lifetime rules for images, atlases, fonts, and text. Include shared references, explicit release, process exit, pending draw work, and shutdown; retain automated graphics tests.
- [ ] Implement and test the documented lifetime rules for sound and music. Include shared references, playback and pause, explicit release, process exit, and shutdown; retain automated audio tests.

## 5. Queries and signals

- [x] Specify C snapshot ownership, ordering, filters, dead creation roots, buffer and allocation failures, and mutation rules in the [C contract](../api/c-contract.md). No user or Lua callbacks run during traversal. Record the existing adjacency and pruning strategy and its measured limits in the [benchmark guide](../../tools/benchmarks/README.md).
- [ ] Finish C and Lua `find`, children, descendants, and tree signals for both relationships and mixed-language processes. Test ordering, dead roots, pruning, snapshot-before-mutation, invalid arguments, and allocation failure without partial mutation.
- [ ] Finish inspector snapshots and affected C/Lua contracts and examples for the final identity and relationship APIs. Check that snapshots do not retain process state or unbounded history.

## 6. Release checks

- [x] Review the current global export table and constant families. Document each current alias in the [global export table](../api/lua-globals.md). `lua_global_inventory` checks the table and rejects duplicates; `lua_import_globals` and `lua_import_atomic` check conflicts and rollback. Future API names are selected in alpha.6.
- [ ] Run the headless, C-only, graphics, audio, mixed C/Lua, deep-tree, long-session, and allocation-failure checks for the final implementation. Run supported sanitizer builds. Record the exact commands and results; fix failures before closing this item.
- [ ] Update the alpha.6 inventory and later documentation, platform, and packaging plans for the final contracts. Keep automated emulator checks in alpha.7 and manual user-flow and device checks in beta.
