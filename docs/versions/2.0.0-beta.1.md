# 2.0.0-beta.1: candidate review and release preparation

Status: in progress. Depends on alpha.7 and alpha.8 acceptance. Review the engine
already delivered; new API families, a complete example catalog, minigames and
a website redesign are not release gates. See the [future roadmap](../roadmap/README.md).
The native engine, SDK metadata and Rust crates use the `2.0.0-beta.1` identifier.
The standard and Rust SDK suites passed on macOS arm64. A beta.1 Rust build
also rejected the accepted alpha.8 SDK as an incompatible native release.

## Checklist

- [x] **Rust experimental policy and Game naming.** Make `Game` the canonical Rust owner, remove `Engine` with migration guidance, preserve constructor/process/window/ownership behavior and native C/Lua contracts. Update examples, CLI templates, reference docs and support limits. Verify construction, spawn/execution, termination/shutdown, installed external Cargo consumers, CLI workflows, native tests and documentation checks. Keep future ergonomics outside 2.0; see the [support policy](../api/rust-support.md), [migration](../development/rust-game-migration.md) and [future proposal](../roadmap/rust-ergonomics.md).

- [x] Record the [C/Lua/Rust API snapshot](../api/beta.1-snapshot.md) for the delivered baseline, including ownership, errors and platform limits. The 18 standard inventory and mapping checks, three asset-disabled Lua inventory checks and both installed crate references passed on macOS arm64. Review any API changes before candidate acceptance under the existing 2.x compatibility policy.
- [x] Complete the [getting-started guide](../site/getting-started.md), [gameplay references](../site/api.md) and [SDK guide](../site/sdk.md) for C, Lua and Rust. Cover scheduler, cancellation, resources, Android exports and unsupported combinations. Strict MkDocs and link checks passed. The native SDK and CLI tests, Rust CLI task and 37 executable Rust guide snippets passed locally on macOS arm64.
- [x] Provide [aligned C, Lua and Rust lessons](../../examples/features/README.md) for startup, process scheduling and loading a shared PNG. All nine variants passed bounded installed-SDK and exported runs on macOS arm64 and Ubuntu x86_64. The Linux Xvfb check verified the rendered tile and background for all three players. CI runs the same verifier. The full catalog and minigames remain future work.
- [x] Verify all claimed macOS, Linux, Windows and Android language/export paths, exact support matrix and continuous checks on the candidate revision. All 23 jobs passed on the [first tested revision](2.0.0-beta.1-acceptance.md). Run the same gate on the revision selected for publication.
- [ ] Manually test installation, project creation, examples, build/run/check/export, exported games, updates and removal on the supported authoring hosts. The [authoring walkthroughs](../development/beta-authoring-verification.md) passed on macOS arm64 and in an Ubuntu x86_64 container. The manual Windows walkthrough remains open.
- [ ] Manually test C/Lua/Rust games on clean supported desktop systems and Android devices. Record revision, platform, architecture and results for every claimed path.
- [ ] Manually check graphics, keyboard/mouse where applicable, physical controllers/hotplug, audible sound/music and mobile background/foreground behavior. Distinguish unsupported capabilities from untested claims. On physical Android arm64 devices, check touchscreen coordinates and rotation, Back, Home and return, a connected keyboard, composition and dismissal with the device IME, and audible WAV/OGG playback before and after backgrounding.
- [ ] Resolve release-blocking issues and rerun affected automated/manual checks on the revised candidate.
- [ ] Review dependencies, licenses, notices, package contents and checksums; verify that players do not need authoring toolchains. The [package audit baseline](../development/beta-package-audit.md) records verified alpha.8 artifacts and the remaining notice, asset and candidate checks.
- [x] Prepare one platform-independent source archive from a selected revision, with public C headers, core, assets, platform code, language bindings, CLI, build/version files, tests, examples and licenses. The [source archive instructions](../development/distribution.md#source-archive) cover revision metadata, SHA-256 and pinned dependency downloads. Two runs on the alpha.8 handoff commit `ed220e7` produced identical archives with all 891 tracked files. Final candidate artifacts remain a separate checklist item.
- [x] Automate source-archive verification: extract into a clean directory, build and test the core without Lua or a graphics backend, then build/install the default desktop configuration and compile/run external C consumers against its public installed API. Verify the recorded revision, archive checksum and required license notices. The [verification command](../development/distribution.md#source-archive) records results, and CI retains the archive, checksum, log and report for each revision.
- [x] Prepare versioned candidate documentation with the [existing MkDocs workflow](../development/publishing.md#prepare-a-candidate-documentation-artifact). The snapshot builds from an exact commit and pins repository links to it. Local integration tests verified versioned URLs, the legacy link and rejection of existing output and invalid revisions. The default Pages workflow still serves the existing URLs.
- [x] Prepare tested release candidates and draft artifacts with their exact source revision, support matrix, checksums, known limits and release notes. The [first beta.1 draft bundle](2.0.0-beta.1-acceptance.md#draft-bundle) passed checksum and revision verification. Regenerate it for the revision selected for publication. Tagging, publication and production signing require explicit authorization.

The source archive supports library users and new language bindings. Use the
public C API and select the required core, assets and platform components. The
CLI remains an optional application for these users. Start with one complete
source distribution; a separate reduced core archive is outside this release
scope. This packaging work belongs to release preparation and does not expand
alpha.7.
