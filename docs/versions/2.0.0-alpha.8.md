# 2.0.0-alpha.8: platform validation and automation

Status: in progress. Depends on [alpha.7](2.0.0-alpha.7.md). Owner scope decision:
validate the delivered engine before expanding the API. The former complete-API
expansion moves to the [future roadmap](../roadmap/api-candidates.md), with no
version assigned. Windows/Android work moves here from the former alpha.9 plan.
No moved item is completed by this reassignment.

## Scope

Deliver Windows and Android support for the current C/Lua/Rust engine and CLI.
Keep macOS/Linux checks. Distinguish authoring hosts from exported-game targets;
Android is a runtime/export target, not a promised Android CLI host. Record
platform versions, architectures, toolchains, host/target combinations and exact
language capabilities before implementation. Do not infer Rust or graphics
support from a successful Lua or headless build.

Automate tests as capabilities arrive. Start with one documented emulator
configuration; extend the matrix only with a concrete need. Keep real-device,
audible-output and complete user-flow review in beta. This version adds only
portability adaptations needed for the existing scope. New general-purpose API
families remain future proposals. If mobile input needs additional operations,
record and approve the smallest platform-specific contract before implementing it.

## Implementation evidence

A8.2 passed on `c49545c` in [Windows run 43437979697](https://github.com/jepemo/malvado/actions/runs/43437979697).
Both headless and graphical SDKs ran in Debug and Release. Each headless profile
passed 203 CTest checks. Each graphical profile passed 202 CTest checks and five
bounded visual checks: C window lifetime, RGBA pixels, clipping, scrolling and
Lua sleep/freeze rendering. Rust core/assets/graphics tests, main-thread
rejection, resource lifetime, input snapshots, silent audio, ABI probes,
installed-crate window consumers and SDK error diagnostics also passed.

The same source passed the existing [macOS/Linux CI](https://github.com/jepemo/malvado/actions/runs/43437979799).
Local macOS Debug/Release graphics verification also passed. Mesa deployment
regressions cover digest rejection, incomplete drivers and per-executable DLL
copying. No Python bytecode/cache files are tracked; Git ignores both forms.

Use `mise run test-platform -- --rust` for headless verification. Use
`mise run test-platform -- --graphics --rust --work build-platform-graphics`
for graphics. Windows graphics uses checksum-pinned Mesa 26.2.6 llvmpipe with
the default OpenGL 3.3 engine and paced silent audio. Mesa stays in test outputs;
it is not installed system-wide or shipped in SDK/game packages. Logs and the
exact supported baseline are documented in [platform verification](../development/alpha8-platforms.md).

A working WGL provider is required. The hosted system provider failed in
[run 43436269922](https://github.com/jepemo/malvado/actions/runs/43436269922), where
raylib 5.5 aborted during window initialization. This unsupported configuration
is recorded as a limit, not a successful error-recovery test. Software rendering,
injected input and silent audio do not establish GPU/device or audible behavior.
Windows media paths are verified with ASCII filenames and spaces; Unicode media
filenames beyond the asset snapshot service remain unverified.

A8.3 implementation now has a Windows child-process adapter with child-local SDK
and Rustup environment values, bounded stdout capture, CRT argument quoting and
exit-code propagation. C/Rust builds retain the existing commands and managed
build markers. Native fixtures cover spaces, empty/quoted/trailing-backslash
arguments, shell metacharacters, missing tools and capture overflow. The local
macOS installed CLI regression passed; native Windows verification is pending.

Windows folder exports now use `.exe` player/native payload names and shared
asset/source filtering. Canonical parent checks, Windows case folding, atomic
no-replace publication and reparse-point rejection protect destinations. Binary
copy and build-marker writes use binary mode. Local installed SDK/archive and
Rust CLI/export regressions passed; native Windows export verification is pending.
