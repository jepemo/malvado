# 2.0.0-alpha.8: platform validation and automation

Status: in progress. Depends on [alpha.7](2.0.0-alpha.7.md). Owner scope decision:
validate the delivered engine before expanding the API. The former complete-API
expansion moves to the [future roadmap](../roadmap/api-candidates.md), with no
version assigned. Windows/Android work moves here from the former alpha.9 plan.
No moved item is completed by this reassignment.

## Scope

Deliver Windows and Android support for the current C/Lua/Rust engine and CLI.
Keep macOS/Linux checks. Distinguish authoring hosts from exported-game targets;
Android is a runtime/export target, not a promised Android CLI host. Record
platform versions, architectures, toolchains, host/target combinations and exact
language capabilities before implementation. Do not infer Rust or graphics
support from a successful Lua or headless build.

Automate tests as capabilities arrive. Start with one documented emulator
configuration; extend the matrix only with a concrete need. Keep real-device,
audible-output and complete user-flow review in beta. This version adds only
portability adaptations needed for the existing scope. New general-purpose API
families remain future proposals. If mobile input needs additional operations,
record and approve the smallest platform-specific contract before implementing it.

## Checklist

- [ ] **A8.1 Support matrix and reproducible commands.** Pin Windows/Android toolchains and emulator configuration; record supported host/target/language combinations, unavailable capabilities and artifact formats. Document local commands and CI commands that use the same scripts.
- [ ] **A8.2 Windows engine and SDK.** Build/run C core, bundled Lua, safe Rust and applicable mixed/ownership tests against installed SDKs. Verify errors, lifetime and optional components. Record graphics/input/audio automation limits with executable evidence.
- [ ] **A8.3 Windows CLI and packages.** Automatically create/build/check/run/export C/Lua/Rust projects, including paths with spaces and missing tools. Run exported games on a fresh Windows runner without compilers or Cargo; check assets, dependencies and notices.
- [ ] **A8.4 Android runtime and language paths.** Deliver window/startup and C/Lua/Rust game paths over the existing scheduler; verify both Lua entry forms. Test resources, packaged assets, shutdown and language-specific failure paths in the emulator. Explicitly record any unsupported path; do not close this gate by testing only Lua.
- [ ] **A8.5 Android exports.** Implement and test CLI debug APK and release APK/AAB generation, configuration validation and dependencies. Test APK installation, launch and cleanup; validate AAB structure separately. Signing configuration and authorized publication remain separate from ordinary test builds.
- [ ] **A8.6 Android behavior.** Automate pause/resume, background/foreground, Back, applicable input, audio state and asset/resource cleanup with bounded timeouts and logs/screenshots. State what the emulator cannot establish. Physical devices and audible checks remain beta work.
- [ ] **A8.7 Continuous verification.** Add native Windows jobs and an Android emulator smoke job while retaining macOS/Linux checks. Run fast relevant checks on PRs, broader matrices periodically and on release candidates. Upload failure evidence; require passing supported-platform checks before accepting a candidate. No store credentials are needed for ordinary CI.
- [ ] **A8.8 Acceptance and documentation.** On one candidate revision, verify the support matrix, clean-runner exports, language parity, licenses and reproducible commands. Carry concrete remaining device checks to beta; keep missing automated capabilities open.

## Implementation evidence

Use `mise run test-platform -- --rust` locally and in the Windows workflow.
It builds Debug and Release headless SDKs, runs C/Lua and Rust tests, moves each
SDK to a path with spaces, runs an offline consumer of the installed Rust
crates, and checks missing/nonexistent SDK errors. It also checks drive, UNC and
Unix path conversion for the native CMake probes. Commands have bounded
timeouts; CI uploads full logs and the generated CRLF fixture on failure.

Local macOS verification passed all 202 C/Lua checks in each configuration,
Rust core/assets tests, installed-crate consumers and SDK error checks.
The documentation checker and its three regression tests also passed with an
ASCII locale. The Windows C build now enables MSVC C11 atomics. Markdown reads
use UTF-8. Atlas fixture checks accept LF/CRLF and generate explicit CRLF input.
Rust normalizes Win32 verbatim SDK paths only when passing them to CMake;
canonical paths still enforce SDK ownership.

The Rust asset, image, font and audio wrappers now share one native path encoder.
Unix byte paths and Windows Unicode validation keep the asset source contract.
This removes Unix-only imports from graphical wrappers without duplicating path
rules. Local all-target graphics/assets compilation passed.

Rust graphical SDK probes now select MSVC `.lib` archives, `.exe` probes and
Windows system libraries. Native thread checks preserve main-thread ownership;
ambiguous or incomplete inventories fail conservatively. The CMake probe uses
the same DLL CRT as Rust and restricts multi-config generation to the selected
profile. Native Windows execution is required before closing A8.2.

The Windows CI matrix now retains headless verification and adds a graphical
SDK entry with `--graphics --rust --work build-platform-graphics`. It uses
OpenGL 1.1 software rendering and paced silent audio. The shared verifier runs
five bounded C pixel/window/scheduler checks, the Rust graphical workspace and
an installed-crate window consumer. Local Debug C/Lua, selected visual checks
and Rust graphics/assets tests passed. Native Windows results remain pending;
see the [graphics limits](../development/alpha8-platforms.md#windows-graphics-verification).

The first graphical Windows run compiled and passed the non-window checks, but
host WGL initialization failed even with OpenGL 1.1. The verifier now pins Mesa
26.2.6 by checksum and deploys llvmpipe beside test executables. It tests the
default OpenGL 3.3 engine without replacing system drivers or shipping Mesa in
SDK packages. Both selected C visuals and Cargo executables use this driver.
