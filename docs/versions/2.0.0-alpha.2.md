Status: the C core, Lua binding, and backend are under validation. The runtime changes passed [GitHub CI for commit `6b0f9cd`](https://github.com/jepemo/malvado/actions/runs/40912423371). ## Acceptance

The scheduler and processes are in the independent C core. Lua coroutines use the same scheduler. CTest covers C, Lua, and a mixed C/Lua path. The runtime changes passed on GitHub runners; contract review remains open. The diagnostic interface in `runtime.h` is experimental. See the [C architecture](../architecture/c-first.md) for the plan and criteria.

## C API

`include/malvado/malvado.h` provides an opaque independent context, creation and destruction, and a logical clock with explicit advancement. Set `MALVADO_BUILD_LUA=OFF` and `MALVADO_BUILD_RAYLIB=OFF` to build and test the core without downloading Lua or raylib. The [C clock example](../../examples/c/clock/README.md) can also use the installed files.

The core supports C processes with callbacks, priorities, signals, trees, FIFO messages, snapshots, and destruction. The Lua binding registers its coroutines with this scheduler. The raylib adapter is separate. There is a headless [C process example](../../examples/c/processes/README.md) and a [C window example](../../examples/c/window/README.md). Set `MALVADO_BUILD_RAYLIB=OFF` to build the Lua runner with a headless backend. The API is experimental. It does not yet guarantee ABI stability.

## Lua API

- `mv.process(fn)` creates a type. Each constructor returns a positive integer ID that is unique during the run. `mv.find(constructor)` returns a new table of live IDs of that type in creation order. It includes sleeping processes and excludes finished processes and processes marked for termination.
- `mv.signal(id, signal)` and `mv.signal_tree(id, signal)` accept `"sleep"`, `"freeze"`, `"wakeup"`, and `"kill"`. The tree operation affects the process and its live descendants at the time of the call. Later children do not inherit the signal. A process marked for termination cannot be reactivated. Invalid signals or IDs cause an error without changing the tree.
- `mv.kill(id)` and `mv.kill_tree(id)` terminate a process or its tree. A coroutine that kills itself continues until it yields or returns. Cleanup occurs at a safe point. A signal sent to another process affects it in the current tick if it has not yet run.
- `mv.status(id)` returns `"running"`, `"sleeping"`, `"frozen"`, or `nil` if the process does not exist or is marked for termination. Suspended processes still exist and keep the runtime open.
- `mv.set_priority(id, value)` and `mv.get_priority(id)` use integers. The initial value is 0. Higher values run first. Ties use creation order. The order is fixed at the start of a tick. A change during a tick applies on the next tick. Invalid IDs cause an error. `self.priority` reflects the priority and is read-only.
- `mv.send(id, value)` and `self:recv()` use a non-blocking FIFO. `nil` means the queue is empty and cannot be sent. C and Lua can exchange booleans, integers, numbers, and binary strings. Strings are copied. Tables and other Lua values keep their identity and can only be sent to Lua processes. A queue holds up to 1,024 messages. Sending to a full queue causes an error. Pending messages are released when the process ends.
- `self` is userdata. The fields `id`, `parent`, `priority`, `status`, and `recv` are protected. Game properties remain writable. `self.parent` retains the original creator ID or `nil` even if the parent dies and the process becomes a root.
- `mv.snapshot()` returns a copy with `tick` and a `processes` list. Each entry has `id`, `parent`, `type`, `status`, `priority`, `messages`, `draw_commands`, and `visible`. It shows the state at the time of the call, including during a tick. It does not include message payloads or call user getters. Changes to the copy do not change the scheduler.

## Drawing and states

`draw_text` commands belong to the process that created them. They are replaced when that process runs again and remain available between presentations. `freeze` keeps the last drawing visible. `sleep` hides it. `wakeup` makes it visible again. `kill` removes it when the process ends. Persistent text created with `write` has a separate lifetime and must be removed explicitly. Sprite rendering and collision checks belong to alpha.3 and are not validated here.

## C interface for tools

`src/runner/runtime.h` provides a diagnostic hook between ticks, copies of `MalvadoProcessInfo` in a caller buffer, signals, pause, and one-tick stepping (`malvado_debug_*`). A snapshot reports the total even when the buffer is smaller. Values are copies and `status` is a static string. Calls are synchronous and must run on the runner thread. There is no concurrent access or network server. An optional frame hook runs before presentation and is used by the graphics test. During a pause, presentation can continue. `step` advances one logical tick, not one Lua line.

This interface supports a future inspector. It does not yet implement an IPC protocol or GUI. The core contains the general scheduler and lifecycle. The binding is in `src/binding/runtime.c` and the graphics backend is in `src/platform/raylib.c`. The public API is not yet final.

## Verification

CTest covers deterministic traces for priority, creation, trees, signals, FIFO, repeated queues, GC release of pending messages, cleanup, and errors with tracebacks. `mixed_host` exercises C/Lua exchange on one scheduler. `debug_host` checks snapshots, commands, pause, and stepping. With `-DMALVADO_VISUAL_TESTS=ON`, `visual_sleep_freeze` checks pixels for freeze/sleep/wakeup and `visual_c_window` opens and closes the C window. These tests require a display or virtual display.

Headless tests, sanitizers, and graphics tests have run on macOS. Earlier Linux ARM64 container tests ran 23 tests, including graphics with Xvfb and software rendering. Clang static analysis has also run on Malvado C code on macOS. The macOS/Linux build, sanitizer, catalog, and Linux graphics jobs [passed on GitHub for `6b0f9cd`](https://github.com/jepemo/malvado/actions/runs/40912423371). Android and Windows are validated in alpha.6. The build downloads Lua and raylib source, and the runtime contains compiled Lua.

IDs increase monotonically and are not reused. Finished slots are compacted after each tick. Capacity retains the peak number of concurrent processes. Lookup is linear. Each tick allocates and sorts an execution snapshot. Measure performance before optimization. Sanitizers cover the tests run; they do not prove that all paths are free of leaks.
