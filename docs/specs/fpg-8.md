# BennuGD 8-bit FPG import subset

Status: the backend-independent C reader is implemented; Lua metadata access, RGBA conversion, and image creation are implemented; indexed PNG and metadata JSON encoding are implemented in C; file conversion and JSON import remain pending.
This subset follows the 8-bit writer and reader in the pinned
[BennuGD revision](https://github.com/SplinterGU/BennuGD/blob/d49f71891f38db9bbf08c0f6f0002007f564a03c/modules/mod_map/file_fpg.c)
and its [palette reader](https://github.com/SplinterGU/BennuGD/blob/d49f71891f38db9bbf08c0f6f0002007f564a03c/modules/mod_map/file_pal.c).
The original project-owned fixture is generated by
`tests/fixtures/fpg/generate.py` and distributed under Apache-2.0.

The selected uncompressed, little-endian format has an eight-byte
`fpg 1a 0d 0a 00 00` header, 768 six-bit RGB palette bytes, and 576 gamma
bytes. Each record has a 64-byte header: signed 32-bit ID, record size,
32-byte name, 12-byte filename, signed 32-bit width, height, and point count.
The writer uses record size zero. Control points are signed 16-bit pairs,
followed by width × height indexed bytes in row-major order. The pair
`(-1, -1)` denotes an undefined control point. The palette and indices must
remain available without conversion; do not silently discard gamma bytes.

For this first subset, accept IDs 1–999 without duplicates, record size zero,
positive dimensions up to 8192, up to 4096 points per record, at most 999
records and at most 64 MiB input. Require complete records and six-bit palette
channels. Reject unsupported magic, version, record size, truncated input,
invalid sizes, duplicate IDs, and out-of-range values. Names and filenames
are fixed byte fields; preserve their bytes. Do not assume text encoding.
Index 0 remains an index in the imported data; transparency policy belongs to
the explicit rendering/conversion contract.

The fixture has IDs 7 and 42, red and green palette entries, indexed pixels,
a defined point and an undefined point. Compare these exact values and every
truncation boundary in C tests. Test malformed fields, allocation failure,
resource cleanup and an installed C SDK consumer. The C parser does not depend
on Lua or a graphics backend. A later increment must define and test Lua access,
rendering or conversion and transparency; do not mark the full FPG item done
until those paths and the required examples are verified. Other FPG depths,
compressed files, writing and binary round trips are outside this subset.

## C reader

Include `malvado/fpg.h` and link `Malvado::assets`. `mv_fpg_parse` borrows the
input during the call and returns an owned copy, or NULL with a static error
message. `mv_fpg_destroy` releases it and accepts NULL. `mv_fpg_at` enumerates
records in file order; `mv_fpg_sprite` finds an ID. Names and filenames are
fixed-size raw byte arrays, not necessarily terminated strings. Sprite pixel
pointers, palette and gamma pointers are borrowed until destruction.
`mv_fpg_point` returns original signed coordinates and a `defined` flag.
Missing IDs, indexes or output pointers return 0 without changing the output.
Palette bytes remain 0–63; no color conversion or transparency is applied.

The parser rejects empty libraries and nonzero record-size fields. The pinned
writer emits zero for that field; other variants remain unsupported. The
truncation test accepts the boundary after a complete first record because it
is itself a valid one-sprite library.

`mv_fpg_copy_rgba(fpg, id, transparent_zero, output, length)` writes one RGBA
pixel per indexed pixel to a caller-owned, non-overlapping buffer of at least
`width * height * 4` bytes. It converts each six-bit channel by shifting it
left by two, as in the pinned reader. `transparent_zero` must be 0 or 1; when
1, palette index 0 has alpha 0. All other pixels have alpha 255. Invalid
arguments or insufficient space return 0 without changing the buffer. Gamma
is preserved as raw data and is not applied. Conversion does not change the
original palette or indices and does not encode PNG.

## Indexed PNG encoding

`mv_fpg_png_size(fpg, id, transparent_zero)` returns the required buffer
size, or zero for invalid inputs. `mv_fpg_copy_png` writes a complete PNG to a
caller-owned non-overlapping buffer and returns 1. An invalid input or short
buffer returns 0 without changing it. The indexed PNG preserves pixel indexes
and palette colors, converted from six-bit channels by shifting left two bits.
The optional index-zero transparency is encoded in a `tRNS` chunk. No gamma
correction or FPG metadata is encoded. The PNG uses uncompressed DEFLATE;
it can be larger than a compressed image. The APIs need neither Lua nor a
renderer. They do not create files; the caller owns file handling.

## FPG metadata JSON

`mv_fpg_json_size(fpg, transparent_zero)` returns the buffer size including
its terminating zero byte, or zero for invalid input. `mv_fpg_copy_json`
writes that many bytes into a caller-owned non-overlapping buffer. It returns
0 without changing the buffer for invalid inputs or a short buffer. The
boolean integer `transparent_zero` must be 0 or 1 and must match the choice
used when writing each sprite PNG. The encoder does not write files.

The deterministic UTF-8 JSON has `schema: 1`, `kind: "malvado-fpg-8"`, a
`transparent_zero` boolean, and `palette_hex` and `gamma_hex` fields. The hex
fields preserve all original six-bit palette and gamma bytes. `sprites` is in
FPG file order. Each entry contains its numeric `id`, `image` (`<id>.png`),
`width`, `height`, full fixed-size `name_hex` and `filename_hex` byte fields,
and zero-based ordered `points` with signed `x`, `y`, and `defined`. The
indexed PNG preserves the pixel indexes and contains the converted palette.
No text encoding is assumed for historical names. The manifest and PNGs do
not preserve a binary FPG file for byte-for-byte reconstruction. The caller
must save each PNG under the specified filename. This FPG-specific interchange
format is distinct from the native atlas schema; an importer for it is not yet
provided.

## Lua reader

With assets enabled, `mv.fpg.parse(bytes)` parses a binary Lua string and
returns an owned FPG object. It raises an error for invalid or unsupported data.
The object is released by garbage collection and works without a window. It can be held in Lua variables and process fields, but is not supported in process defaults.
The methods use the C reader and return independent Lua values:

- `fpg:count()` returns the number of sprites. `fpg:id_at(index)` returns the
  ID in file order, with a one-based index, or `nil` if it is absent.
- `fpg:sprite(id)` returns a table with `id`, `width`, `height`, `point_count`,
  binary `name_raw` (32 bytes), `filename_raw` (12 bytes), and `pixels`, or
  `nil` if the ID is absent. Names are fixed-size bytes, not guaranteed text.
- `fpg:point(id, index)` returns `{x, y, defined}` for a zero-based point, or
  `nil` for an absent ID or index. Undefined points retain their raw values.
- `fpg:palette()` returns the 768 original six-bit RGB bytes and `fpg:gamma()`
  returns the 576 original gamma bytes.
- `fpg:json(transparent_zero)` returns the metadata manifest as a JSON string
  without a trailing zero byte. The optional flag is a boolean and defaults to
  false. It works without a window. Use the same flag for every sprite PNG.
- `fpg:png(id, transparent_zero)` returns an indexed PNG byte string, or `nil`
  for an absent ID. The optional flag is a boolean and defaults to false. It
  works without a window and uses the C PNG encoder described above.
- `fpg:rgba(id, transparent_zero)` returns an RGBA byte string or `nil` for an
  absent ID. The optional flag is a boolean and defaults to false. Conversion
  has the same channel and transparency behavior as `mv_fpg_copy_rgba`.

`fpg:image(id, transparent_zero)` creates an independent managed image from a
sprite. The optional boolean defaults to false, as for `rgba`; absent IDs
return `nil`. A valid ID requires an open graphics window. Image creation
raises an error if conversion or upload fails. The image keeps its pixels
after the FPG object is collected and can be used with `draw_image`, image
regions, and `self.graph`. It follows the normal image resource lifetime.
An automatic graph collider uses image bounds. FPG control point zero is not
implicitly applied as the image pivot; read it with `fpg:point` and use an
explicit image-region pivot when needed.

The `mv.fpg` namespace is separate from the legacy global `fpg` graphics
helper. The `fpg` object can still be inspected in headless mode, but image
creation requires a window.
