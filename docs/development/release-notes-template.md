# Release note template

Copy this outline into `docs/changelog/VERSION.md`. Keep the headings that
apply. Replace all placeholder text during candidate preparation. Publication
dates and status are recorded separately after the GitHub release is public.

```markdown
# Malvado <version>

## Highlights

- Explain what game developers can do and why it matters.

## Added

- Describe the feature and link to a runnable example or reference.

## Changed

- Describe the observable behavior and the affected languages or platforms.

## Fixed

- Explain the problem the player or game developer saw.

## Deprecated

- Give the replacement and any confirmed removal schedule.

## Removed

- Name the removed behavior and its replacement where available.

## Breaking changes

- Give the old and new behavior, the reason for the change, the affected
  users, and the required action.

## Upgrade from <source version>

- Give a verified before and after example or link a longer migration guide.

## Known limitations

- State the relevant limits of the delivered version.
```

Use **Improved** or **Security** when appropriate. Put optional comparisons,
issue references, or asset and checksum details after the user-facing notes.
